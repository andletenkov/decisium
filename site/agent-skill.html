Agent skill

Install it into your coding agent from node_modules/decisium/skills/decisium/SKILL.md.

Decisium runs each Step by asking Jev, a model that only picks among offered answers. Code decides pass/fail. A Step's wording decides most outcomes, so write the wording from evidence: docs/cookbook.md lists the wordings that pass on the examples and the ones that fail, with why. Read it before writing a Step. It is the single source of the rules; this skill is the procedure.

Write

  1. Write the feature: an @url:<start url> tag, then one Scenario per user journey, each starting from a fresh browser. Model each Step on a ✓ row of the cookbook for its kind (navigate, type, select, act, attempt, value / presence / scoped / state check, memory, secrets). Quote every value the Step uses and every value a check compares. Credentials go in as "$NAME" placeholders, with the variables set in the environment or .env.
  2. Run npx decisium lint <file.feature>. It shows how each Step will be read (kind, quoted values, placeholders) and flags the cookbook's failing wordings with ⚠. Done when every ⚠ is reworded away, or kept on purpose with a # comment saying why (for example, a scenario meant to fail).

Run and repair

  1. Run npx decisium run <file.feature> (live Jev the first time; it records a cassette next to the feature).
  2. On a failure, read runs/<id>/report.md: the Step at file:line, Jev's answers with probabilities, the page text around the element, and a rerun command for that scenario. Classify each failure:
    • The app is wrong (ASSERTION_FAILED, BLOCKED with the expected control truly missing): keep the Step, and report the app behaviour.
    • The wording is unclear (AMBIGUOUS, UNVERIFIABLE, a check that picked the wrong element): reword using the cookbook row whose "Why" matches Jev's split, then rerun just that scenario.
    • A marginal pass warning means the pass rested on a barely-confident answer. Treat it like an unclear wording.
  3. Keep the test's intent fixed while rewording. The quoted expected values and the area a check looks in stay as written. A rewording that makes a check pass by reading a different element (a link instead of the heading, a search box instead of the article) is a false pass. Compare Jev's subject in report.md with what the scenario means.

Done when the run passes, or every remaining failure is classified as the app being wrong, with the evidence line from report.md.
